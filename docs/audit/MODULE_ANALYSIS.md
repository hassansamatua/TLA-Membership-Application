# Module Analysis

Status legend (from brief): Implemented and verified · Implemented but not tested · Partially implemented · Documented but not implemented · Broken · Not found · Unknown.

## 1. Registration & approval
- Flow: `app/auth/register/page.tsx` → `POST /api/auth/register` (transaction: `users` + `user_profiles`, duplicate email/NIDA check) → user `is_approved=0` → admin `app/admin/requests` → `POST /api/admin/approve-member` (DB `is_admin` check; sets approved; `initializeUserCycles` from **legacy 50k engine**; `INSERT IGNORE memberships`; `sendApprovalNotification` email).
- Runtime: registration returned 201 and created an unapproved user; login blocked until approval (source); after approval (set directly in DB) login succeeded. Approve endpoint itself not exercised at runtime.
- Issues: membership number generated by DB trigger + other generators (divergent); approval bypass via `POST /api/admin/payment` (sets `is_approved=1`, no admin check).
- Status: **Implemented but not tested** (register: verified).

## 2. Profiles & categories
- `app/api/user/profile`, `app/api/auth/profile`, `app/dashboard/complete-profile`, `lib/profileCompletion.ts`; flattened profile columns via migrations.
- Category: `users.membership_type` enum(librarian, regular, organization) vs `payments/memberships.membership_type` enum(personal, organization); `user_category` column missing.
- Status: **Partially implemented**.

## 3. Member status lifecycle (approval/suspension/termination)
- `memberships.status` enum includes `suspended`, but no route sets suspension/termination; soft delete → `deleted_users` + restore exists (`admin/users/restore`).
- Status: approval implemented; suspension/termination **Not found**; delete/restore implemented but not tested.

## 4. Cycles, renewals, penalties, advance payment, first-cycle exemption
See `BUSINESS_LOGIC_AUDIT.md`. Engines exist and compute at library level (verified by tests) but disagree; routes use different engines. Status: **Partially implemented / inconsistent**; advance payment **Broken** (inconsistent windows, pending-only rows); refunds **Broken**.

## 5. Payments

## 6. Admin dashboard & reports
- Dashboard charts (`MULTI_CHART_DASHBOARD.md`), `admin/reports/*` (runtime 200 — data returned, but includes orphan/test data and is unauthenticated), `reports/generate` export (CSV/XLSX), `reports/send-email`.
- Bulk actions/export on `app/admin/users/page.tsx` are `TODO`.
- Roles: only `is_admin` boolean; `role` column always `member`; no finance-officer role or permission model. RBAC **Not found** beyond admin/member.
- Settings: `site_settings` + `/api/settings`, `admin/membership/settings` — implemented but not tested.
- Audit activity: `audit_logs`/`login_logs` never written → **Not found** (tables only). `admin/reports/activities` derives activity from other tables.

## 7. Notifications
- Email: nodemailer wrappers ×3; approval/rejection/reminder/penalty templates in `lib/notificationService.ts`; idempotency via `hasNotificationBeenSent`; cron route gated by `CRON_SECRET`. Implemented but not tested (no SMTP).
- SMS: `sendSmsNotification` stub (Twilio commented). **Documented but not implemented**.
- In-app: `news_notifications` + `user_notification_reads` — implemented but not tested.
- Failure handling: send failures logged and swallowed; no retry queue.

## 8. Events
- Admin CRUD (`admin/events`, TS errors), member registration with duplicate & capacity check (non-atomic), event payments tables (AzamPay), attendance table unused (0 rows, no UI writes found). Events: implemented but not tested; attendance **Not found** (schema only); analytics partial.

## 9. Content/CMS, contact, messaging
- CMS tables + admin content pages: implemented but not tested. Contact form writes `contact_submissions` (unauth, no rate limit/captcha). Messaging scoped by token user id; `messages` table missing from dump → Unknown in prod.

## 10. Membership cards
- 8 generators (`lib/membershipCard*.ts`) + `app/admin/cards`, `app/dashboard/membership-card`; visibility gated by `canViewMembershipId` (admin plan engine). Implemented but not tested; duplication.

## 11. Ops/debug modules shipped in app
`import-*`, `migrate-*`, `verify-migration`, `fix-*`, `setup/*`, `debug/*`, `test-*`, `payments/create-test`, `payments/activate-test`, pages `fix-auth`, `test-membership-card` → should not be deployable.
